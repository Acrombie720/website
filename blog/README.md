# The blog

`fluencyfox.ai/blog`, built with [Astro](https://astro.build). Everything else
on the site is generated by `build/build.mjs`; this folder owns `/blog` and
nothing else.

## Writing a post

One Markdown file in `src/content/posts/`. The filename is the URL, so
`ai-fluency-is-not-prompt-writing.md` publishes at
`/blog/ai-fluency-is-not-prompt-writing`. Pick the slug carefully and do not
change it after publishing, because that is the URL Google will have indexed.

```markdown
---
title: "Under 70 characters, with the words someone would search for"
description: "70 to 160 characters. This is the line that shows under the title in search results, so write it for a human who is choosing which result to click."
published: 2026-09-24
tags: ["Hiring", "AI fluency"]
---

The first paragraph. Then `## Section headings`, lists, quotes, tables and
code blocks, all of which are already styled.
```

Optional front matter: `updated` (set it when you revise a post, it goes into
the sitemap and the structured data), `author` (defaults to Fluencyfox),
`draft`, `ogImage`, `canonical`, `noindex`.

The lengths are enforced. A title or description outside the limits fails the
build rather than shipping something Google will truncate.

`draft: true` renders in dev and never appears in a build, so an unfinished
post can sit in the folder safely.

## Seeing it

```bash
npm run dev:blog          # from the repo root, http://localhost:4322/blog
```

Drafts are visible here. The logo and the social cards are served out of
`fluencyfox-site_6/` so the page looks like the real thing.

## Publishing

```bash
npm run build             # from the repo root
```

That runs, in order: this project, the social cards, the page generator, the
CSV and the Data Index card. Then commit `fluencyfox-site_6/` as usual and
Cloudflare Pages picks it up.

Building from the root matters. The blog build writes
`build/generated/blog-posts.json`, and three things downstream read it: the
sitemap, the blog column in the footer of every other page, and the 1200x630
social card rendered for each post.

## How it fits the rest of the site

- **URLs have no trailing slash.** `emit.mjs` writes the index to
  `fluencyfox-site_6/blog.html` and posts to `fluencyfox-site_6/blog/<slug>.html`,
  because Cloudflare Pages serves a file at `/path` and a folder at `/path/`.
- **One sitemap.** Blog URLs go into the existing `sitemap.xml`, the only one
  `robots.txt` points at.
- **One set of chrome.** The header and footer are the same markup and the
  same `build/assets/css/shell.css` as every generated page, and the palette
  matches the research pages.
- **No tag archive pages.** Tags show on a post and pick the related links. A
  page per tag would be thin and would compete with the posts themselves.
- **The CSS is inlined** in every page, so nothing but the web fonts blocks
  the first render.
